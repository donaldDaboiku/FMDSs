# FMDS production checklist

## 1. Environment
- Copy `backend/.env.example` -> `backend/.env` (local Node runs).
- Copy root `.env.example` -> `.env` (Docker Compose).
- Set real `MONGODB_URI` / `JWT_SECRET` / `CLIENT_ORIGIN`.
- Frontend same-host API base: `REACT_APP_API_BASE_URL=/api` (Docker build sets this).
- Never commit `.env` files.

## 2. Local Docker (app + Mongo)
```bash
cp .env.example .env
# Edit JWT_SECRET and CLIENT_ORIGIN

docker compose up -d --build
```

- App: `http://localhost:5000` (or `PORT` from `.env` / shell)
- Health: `GET /api/health`

```bash
docker compose logs -f app
docker compose down
```

## 3. Docker with MongoDB Atlas (no local mongo)
```bash
# .env must include Atlas URI + public origin
MONGODB_URI=mongodb+srv://USER:PASS@cluster/fmds
JWT_SECRET=long-random-secret
CLIENT_ORIGIN=https://your-app.onrender.com

docker compose -f docker-compose.yml -f docker-compose.atlas.yml up -d --build
```

## 4. Deploy on Render (recommended cloud path)
1. Create a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster.
2. Allow Render egress / `0.0.0.0/0` in Atlas Network Access (tighten later).
3. In Render: **New → Blueprint** and connect this GitHub repo (`render.yaml`).
4. Set sync:false env vars in the Render dashboard:
   - `MONGODB_URI` — Atlas connection string
   - `CLIENT_ORIGIN` — your Render URL, e.g. `https://fmds.onrender.com`
5. Deploy, then verify `https://YOUR-SERVICE.onrender.com/api/health`.

`JWT_SECRET` is auto-generated by the blueprint.

## 5. Local Node single-host
```bash
npm run install:all
npm run build
# backend/.env: NODE_ENV=production, SERVE_CLIENT=true
npm start
```

## 6. Verify
- `GET /api/health` → `{ "status": "ok", "db": "connected" }`
- Login works; protected routes still load on refresh
- CORS origin matches the browser URL exactly (scheme + host + port)

## 7. Ops notes
- Prefer Atlas in cloud; avoid exposing Mongo publicly longer than needed.
- Rotate `JWT_SECRET` if it was ever shared or committed.
- Uploads on free Render disks are ephemeral — use object storage if files must persist.
- CRA frontend `npm audit` noise remains until a bundler migration.
- GitHub Actions CI runs on push/PR to `main`.
